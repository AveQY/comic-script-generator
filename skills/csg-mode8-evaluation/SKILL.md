## 模式八：小说爆款评估（Blockbuster Potential Forecast）

> **借鉴自**：`project-quality-audit` v1.1 的「小说爆款评估」功能 + `cheat-on-content` 方法论。
> **与主流程的区别**：模式一至七管"生成"，模式八管"评估已生成的项目哪些值得继续投入"。
> 写完一部小说或漫画后，用本模式评估市场潜力，决定优先发布时间和推广方向。

### 触发条件

- 用户问"哪些可能是爆款"
- 需要决定优先投入哪个项目继续写/渲染/推广
- 需要在项目组合中识别"潜力高但未完成"的种子
- 需要评估整个项目库的市场竞争力

### 6 维评估框架

每个维度 0-5 分，整数打分。**先盲打，再对比，30 秒/维度，相信第一个整数。**

| 维度 | 权重 | 代号 | 0 分（低） | 5 分（高） |
|------|------|------|-----------|-----------|
| **概念钩子** | ×2 | CH | 烂大街设定，毫无新意 | 让人想立刻转发给朋友："卧槽这设定绝了" |
| **情感共鸣** | ×2 | ER | 读完无感，像看说明书 | 读到鼻酸/笑出声/立刻想评论 |
| **人设记忆点** | ×1.5 | CA | 看完记不住角色名 | 角色名能成梗/标签，读者自发二创 |
| **文笔质感** | ×1.5 | PQ | 纯信息流，毫无文学性 | 第一段就让人想截图发朋友圈 |
| **改编潜力** | ×1.5 | AD | 只能当小说，无法视觉化 | 一看就是短剧/漫画/短视频素材 |
| **完成度** | ×1 | CO | 开了头就断，仅 3 章 | 完整闭环，可发布可推广 |

#### 综合分公式

```python
composite = (CH×2 + ER×2 + CA×1.5 + PQ×1.5 + AD×1.5 + CO×1) / 9.5 × 10
```

结果范围 0-10。权重总和 9.5，归一化到 10 分制。

#### 权重设计理由

- **CH / ER 最高（×2）**：概念和情感是小说出圈的第一驱动力。再好的文笔，设定无聊也白搭
- **CA / PQ / AD 中等（×1.5）**：人设、文笔、改编潜力是放大器，但不是启动器
- **CO 最低（×1）**：完成度是硬约束，但"未完成"不代表概念差——潜力高的项目更值得优先投入写完

### Bucket 分级

| Bucket | 分数区间 | 解读 | 行动建议 |
|--------|---------|------|---------|
| 🔥 现象级 | ≥8.5 | 全网讨论潜力 + 改编签约级别 | 优先写完，准备推广 |
| 💥 爆款 | 7.0–8.4 | 出圈，有二创/读者推荐 | 继续投入，规划发布 |
| ✅ 中上 | 5.5–6.9 | 有读者口碑，质量在线 | 稳住节奏，持续产出 |
| ⬜ 普通 | 3.0–5.4 | 写了但没人讨论 | 审视概念是否需要升级 |
| ⛔ 低质 | <3.0 | 不值得继续 | 考虑弃坑或大幅改版 |

### 盲预测纪律（借鉴 cheat-on-content）

1. **先盲打再对比**：打分前绝不看其他项目的分数，不被锚定
2. **30 秒/维度**：超过这个时间你是在合理化，不是在打分。相信第一个整数
3. **锚点验证**：盲打完后，找 2-3 个 composite 接近的项目做对比，验证排序是否合理
4. **预测不可改**：一次打完、落盘，留给未来的复盘做校准。不要之后偷偷改分
5. **警告：冷启动期**：第一次跑时没有任何历史数据，锚点不可用。预测文件标记 `锚点对比：N/A（cold-start）`

### 已知限制（Known Limitations）

这份 rubric 注定会打错的地方：

1. **题材热度轮动**：AI 题材今天火，下个月可能凉。纯爱/治愈系反而不易过时
2. **平台适配差异**：番茄 vs 知乎 vs 小红书的读者偏好完全不同。一份分打不出平台差异
3. **更新频率未计入**：周更 vs 月更的实际读者粘性不同，但 rubric 不捕捉
4. **概念密度惩罚**：一个设定塞太多自创术语（>3 个新概念）增加阅读负担，rubric 没惩罚这个
5. **作者成长**：后期文笔可能比前期好，rubric 只基于当前抽样打分

### 评估流程

按以下步骤对每个项目执行：

#### 步骤 1：收集数据

1. 读 `summary.md` 的"一句话卖点" → 判断 CH（概念钩子）和 ER（情感共鸣）
2. 读 `characters.md` 或 `chars.md` → 判断 CA（人设记忆点）
3. 抽第一章开头 150-200 字 → 判断 PQ（文笔质感）
4. 读最后一章标题/开头 → 判断 CO（完成度）
5. 综合判断 AD（改编潜力）

#### 步骤 2：计算分数

```python
composite = (CH×2 + ER×2 + CA×1.5 + PQ×1.5 + AD×1.5 + CO×1) / 9.5 × 10
```

#### 步骤 3：锚点对比

对 top 项目，两两对比验证：

```
项目A（composite=7.8）vs 项目B（composite=7.5）
→ 差异在哪？A 的 ER 高 1 分，B 的 CO 高 1 分
→ 合理吗？A 的设定确实更动人，但 B 更完整
→ 排序合理，无需调整
```

#### 步骤 4：输出报告

按 bucket 降序输出：

```
🔥 现象级（≥8.5）
  - 项目名（composite: X.X）— 理由

💥 爆款（7.0–8.4）
  ...

✅ 中上（5.5–6.9）
  ...

⬜ 普通（3.0–5.4）
  ...

⛔ 低质（<3.0）
  ...
```

### 快速评估脚本

```bash
cd ~/.hermes/skills/writing/project-quality-audit
python3 scripts/market-potential-score.py --project 项目名
```

或对所有项目做批量扫描：

```bash
python3 scripts/market-potential-score.py
```

### 写在每个项目上

写完一个项目后，建议立即做一次爆款评估，记录预测结果。这样：
- 如果项目后来真的火了，可以验证 rubric 的准确度
- 如果项目没火，可以复盘哪个维度打高了，调整权重
- 积累足够多的样本后，可以校准出自己的 rubric

**这本身就是 cheat-on-content 的校准循环：打分 → 预测 → 发布 → 复盘 → 进化。**
