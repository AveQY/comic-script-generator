# 轻小说平铺结构模式（project-root flat structure）

## 适用场景

项目已在 `init_project.py` 等流程中初始化完成（`config.json`、`style_guide.md` 已存在），但未创建 `light_novel/` 子目录，章节文件直接放在项目根目录下。

典型状态：
```
projects/<项目名>/
├── config.json          # 已配置 content_mode, category 等
├── style_guide.md       # 已存在
├── characters.md        # 空白占位 / 待覆写
├── summary.md           # 空白占位 / 待覆写
├── foreshadowing.md     # 空白占位 / 待覆写
├── chars.md             # 部分项目使用（与 characters.md 等效）
├── 第一章_入场券.md      # 章节文件在根目录
├── 第二章_画家的世界.md  # 不在 light_novel/ 下
└── 第三章_裂缝.md        # 命名格式：第X章_标题.md
```

## 与标准 light_novel/ 子目录模式的区别

| 维度 | 标准模式 | 平铺模式 |
|------|---------|---------|
| 章节目录 | `light_novel/` | 项目根目录 |
| 文件命名 | `ln001_标题.md` | `第一章_标题.md` |
| 对白格式 | `「台词」——角色名` | `角色名「台词」` 或 `「台词」——角色名` |
| validate_light_novel 兼容 | ✅ 自动发现 ln*.md | ⚠️ 需要手动指定文件路径 |
| heredoc 检测 | ✅ 默认覆盖 | ✅ 同标准模式 |

## 适用条件

- 项目已有 `config.json` 且 `content_mode` 已配置
- 不需要 Reader 书架透过 `light_novel/` 目录自动发现章节（或 Reader 配置已适配根目录文件）
- 章节数量少（3-5 章）或为短测/试读项目
- 用户没有明确要求 `light_novel/` 子目录结构

## 章节文件命名约定

```
第一章_入场券.md
第二章_画家的世界.md
第三章_裂缝.md
```

命名规则：
- `第X章` 用中文数字（第一章、第二章……）
- 下划线分隔
- 标题用 2-5 个中文字，概括章内核心事件或意象
- 避免含 `/ \ : * ? " < > |` 等文件系统非法字符

## 对白格式：角色名前缀模式

在标准轻小说模式中，skill 文档推荐 `「台词」——角色名`（对白后置角色名）格式。平铺结构中也可以使用**角色名前缀模式**：

```
林深「准备好了吗？」
顾城「记住，你会以平行世界的自己的身体存在，时间是三天左右。」
苏晚棠「你已经调查这个体验馆多久了？」
```

格式规则：
- `角色名`（不含空格）紧接 `「`
- 对话内容在 `「」` 内
- 角色名后无冒号/空格
- 叙述句（动作、表情、心理）可以跟在对话后另起一行，不强制同行

### 两种格式对比

```
# 格式A：角色名前缀（本模式）
林深「你觉得这真的是平行世界吗？」

# 格式B：对白后置角色名（标准轻小说模式）
「你觉得这真的是平行世界吗？」——林深
```

两种格式在中文轻小说中都常见。差异在于：
- **格式A**：阅读时先知道谁说话，再读内容，适合快速对话场景
- **格式B**：阅读时先读内容再知谁说话，适合制造悬念或语气反转

### 验证注意事项

`validate_light_novel.py` 默认正则 `^「.+?」——.+$` 只能匹配格式B。如果用格式A（角色名前缀），对白统计会为 0，触发 "too few dialogues" 误报。

**解决方案**：跑验证时传自定义对白正则，或把格式A的对话行临时转为格式B再验证。两种格式在正式交付时均可使用，取决于项目需求。

自检命令（格式A版本）：

```python
import re
# 匹配 角色名「台词」格式
fmt_a = len(re.findall(r'^[\u4e00-\u9fff]{2,4}「.+?」', text, re.M))
# 匹配 「台词」——角色名 格式
fmt_b = len(re.findall(r'^「.+?」——.+$', text, re.M))
print(f'format-A={fmt_a} format-B={fmt_b}')
```

## 插图标记

与标准模式一致，每章 ≥3 个 `<!-- ILLUST_N -->` 标记：

```markdown
正文段落……

<!-- ILLUST_1 -->
【插图：场景描述文字，供后续渲染参考】

正文继续……
```

标记出现在正文段落之间，编号从 1 开始递增，每章独立编号。

## 章末钩子

与标准模式一致，每章末尾有 `## 章末钩子`：

```markdown
## 章末钩子
<强悬念/未解决动作/情感冲击句>
```

钩子可以是单句，也可以包含双段（例如 钩子上 + 钩子下 用分隔线分开）。

## 平铺 ↔ 标准模式迁移

如果项目初期用平铺结构，后续需要接入 Reader 书架的标准发现逻辑：

1. 创建 `light_novel/` 目录
2. 将 `第一章_入场券.md` 重命名为 `light_novel/ln001_入场券.md`
3. 将 `第二章_画家的世界.md` 重命名为 `light_novel/ln002_画家的世界.md`
4. 按 `ln` 前缀+三位数字重新编号

迁移后字符数、对白统计、插图标记、钩子内容均不受影响。
