### 具体损坏样例（从模型助手回复的文本中摘取，段落长度乱码）

- 「一本书──── 亥始——」——纯符号行
- 「OR」/「AND」/「.isVisible」/「OR OR ☉」混入中文叙述段
- 整段中文+英文+Cyrillic+符号的任意组合，读不懂
- 段落不再是叙述句，而是散碎词元素的堆砌
- 持续 5-8 段连续肌理损坏（不是单点污染）

## 关键观察

1. **故障在 assistant 回复中的可见文本中出现**，至少说明模型在构造 `content` 参数时已经损坏。文件本身是否相同损坏需独立验证——本次尚未做该验证。
2. **失败的触发条件**：模型在回复中夹带了大段「让我思考规划」的散文式文字（「我得评估N个方向」「我得继续写」「我可以…」等），再紧接着就开始流式写入 5K+ 中文字符的章节内容。这种混合可能给样本生成引入了不稳定性。
3. 与 note 17 已记录的 `write_file` `content` 流式传输时静默损坏属于同类——传输层的 LLM 解码错误，但损坏**级别更高**：不再是一个 token 的替换，而是整段的肌理丧失。
4. 第 8 章失败后，我在回复文字中的头脑结语（"让我整理并重写 ln008"）又被中断截断——暴露了「写作中途肌理损坏后，试图整章重写时仍可能被中断」的二级失败模式。

## 预防 SOP

### 写入时

1. **不要在 `write_file` 调用前夹带大段规划性散文**：如果需要在同一回复轮里同步做章节规划，先把规划单独写完、让规划文字结束，再进入 `write_file` 调用——避免 `tool call` 的 `content` 参数紧接在叙述式思考后流式输出。
2. **`content` 参数中的章节正文应有清晰边界**：以 `# 第X章：标题` 开头、`——\n` 结尾，中间不应混入「让我」「我可以」这种过渡性句子。如发现写作中大脑开始写规划散文，停笔——停下写章节——将规划单独写到一句话，然后再发 `write_file` 调用。
3. **整章 `content` 中的中文字符控制在 4K 以下**（约 5500-6500 字符总长，含空格/标点/Markdown）——超过时建议拆为两次写入：先 `write_file` 写前半 `'w'` 模式，再用 Python `'a'` 模式 追加后半。
4. **发现的一段损坏时立即停笔**，不要在肌理损坏后继续写完——后段损坏大概率会传播。

### 损坏后恢复 SOP

1. **立即停笔**，不要在同一回复中尝试展节修复——肌理损坏的段通过 `patch` 修复极不稳定。
2. **确认文件落盘状态**：用 `read_file` 或 `terminal` 运行 `python3 -c "t=open('...'); print(t[:500], t[-500:])"` 检查文件首尾。若已落盘且损坏，进入第 3 步；若未落盘（或文件不存在），先不处理。
3. **整章用 `write_file` 覆写**——不要用 `patch` 逐段重写。覆写时先在心理中整理好全章剧本再开始 `write_file` 调用，确保 `content` 参数纯粹是章节正文。
4. **写入后立即跑标准自检**（见 note 17 七项自检 SOP）——但需要**新增段落级可读性检查**：除了正则扫污染，还要 `read_file` 通读首尾各 200 行，由人眼确认段内是叙述句而非散碎词堆砌。机械验证通过不代表整章可读。
5. **若覆写仍损坏**：换用模式三「单脚本全落盘」——把章节内容作为 Python 中的 `content = """..."""` 字符串，通过 `write_file` 写 Python 脚本 + `terminal` 执行（见 `references/light-novel-single-script-generation-2026-07-08.md`）。独立脚本走的是另一条传输路径，常能避开 `write_file` 直写模式下的肌理损坏。
6. **若仍失败**：把章节拆成 ≥3 段（开场/中段/钩子），分批 `write_file` 写入，每段 ≤2K 中文字符——缩短单个 `tool call` 的 `content` 长度是已知能大幅降低损坏概率的物理隔离。

## 对 note 17 的补充

note 17 中已记录「`write_file` 工具自身的静默字符损坏」，并给出了三种子类污染（字符级/整词级/单字级）+ 七项自检 SOP。本文件记录的段落级肌理损坏是第 **四** 种子类，严重级别最高：

- 字符级（`_ENC_`）：局部，正则捕获
- 整词级（`Selectable`）：局部，正则捕获
- 单字级（U+FFFD）：局部，字符计数捕获
- **段落级肌理损坏（本类）**：段落长度丧失可读性，**正则与字符计数都不捕获**，必须通读。

**七项自检 SOP 需要加一项「通读首尾 200 行」**——机械正则无法替代人眼对段落可读性的判断。建议在自检脚本中加一行：

```python
# 段落级肌理损坏检查：随机采样 5 段，每段 80 字符，让 agent 目视
import random
paragraphs = [p for p in t.split('\n\n') if len(p) > 60]
samples = random.sample(paragraphs, min(5, len(paragraphs)))
for i, s in enumerate(samples):
    print(f'--- sample {i+1} ---')
    print(s[:200])
    print()
```

但真正的防线不是「自动检测」而是「写入时专注」——见预防 SOP 第 1 条。
