# 子代理大纲漂移：长篇正文委托的失效模式与对策

> 来源：2026-07-21《替考AI》32 章生成实战。3 个子代理（带完整大纲 context）各自写出 3 个完全不同的故事，全部偏离已确认大纲。最终改为主会话直接 write_file 逐章写完全部 32 章。

## 失效模式

委托子代理（leaf agent）写长篇小说章节时，即使 context 里附了**完整大纲、主角设定、每章标题和钩子**，子代理仍会：

1. **自创主角**：大纲主角是「林晚舟（班主任）+ 陈默（学生）」，子代理交付「李想（复读生）」「林晚+江澈」等全新人物线。
2. **自创设定**：大纲是「老师追查学生作弊」，子代理写成「学生被 AI 招募替考」。
3. **自创剧情结构**：大纲 32 章四卷，子代理按自己的理解重排，甚至只交付「前 4 章+问你接下来怎么写」的元回复。
4. **文件名不遵守**：约定 `ln001_完美的答案.md`，交付 `ln001_差生的最后一天.md`。
5. **meta 回复冒充交付**：子代理正文没写文件，只回了「以上为开篇四章，需要我续写吗？」——文件系统里什么都没有。

**根因**：子代理没有会话上下文，长 context（大纲数千字）在子代理注意力里被压缩/忽略；子代理倾向于"生成一个像样的小说开头"而非"按给定大纲的第 N 章写正文"。

## 与短剧分镜委托的对比（为什么分镜能成、正文不能）

| 维度 | 短剧分镜（模式七，实测 55 集成功） | 长篇小说正文（本次，失败） |
|---|---|---|
| 单文件长度 | ≤4000 字符，硬约束 | 4000-4500 字/章，软目标 |
| 结构刚性 | 表格/镜号/尾帧，格式强校验 | 自由散文，无机械校验点 |
| 素材来源 | 已有小说章节全文（逐字搬运台词） | 只有大纲（需原创扩写） |
| 发挥空间 | 小（格式+原文双重锁定） | 大（大纲只是方向） |

**结论**：子代理适合「素材已在、格式刚性」的转换型任务；不适合「只有大纲、需原创」的创作型任务。

## 决策树

```
用户要求生成小说章节正文
│
├─ 有源文本可转换（小说→分镜、漫画稿→小说导出）
│   └─ ✅ 可用子代理（附绝对路径 + 精确格式模板 + 硬字数约束）
│
├─ 只有大纲需原创，且章节数 ≥ 4
│   └─ ❌ 不要用子代理 → 主会话直接 write_file 逐章写
│       （一次一章，写完立即 grep 验证角色名/章末钩子存在）
│
└─ 只有大纲需原创，且章节数 ≤ 3 的试水
    └─ ⚠️ 可试子代理，但 context 必须包含：
        ① 主角姓名/身份一句话锚点（放在 context 最开头，重复 2 次）
        ② 每章标题 + 100 字内核心事件（不是整份卷纲）
        ③ 明确禁令：「禁止自创主角名、禁止改变主角身份、禁止 meta 回复，必须 write_file 落盘」
        ④ 交付后立即验证：grep 主角名命中数 > 0，否则视为失败，不再重试，改主会话直写
```

## 验证三件套（子代理交付后必跑）

```bash
cd <项目>/light_novel
# 1. 文件真的落盘了吗（防 meta 回复冒充）
ls ln*.md | wc -l
# 2. 主角名真的对了吗（防自创主角）
grep -l "林晚舟" ln*.md | wc -l   # 期望 = 章节数
# 3. 章末钩子真的在吗
for f in ln*.md; do echo "$f: $(grep -c '章末钩子' "$f")"; done
```

任一不达预期：**不要重试子代理**（重试大概率产出第三个新故事），直接主会话 write_file 重写。

## 主会话直写的节奏控制

- 一次 write_file 写一章（≤4K CJK 中文字符，遵守 write_file token 上限）。
- 写完一章立即 `wc` + grep 验证，再写下一章。
- 32 章实测约 40 次 write_file 调用完成，全程无漂移——因为大纲在执行者自己的上下文里。
