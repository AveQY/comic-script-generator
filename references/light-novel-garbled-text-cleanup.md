# 轻小说跨语言乱码污染检查与修复（2026-07-08）

## 背景

用 LLM 生成中文长篇轻小说正文时，输出常混入英文碎片和乱码标记。这些不会被 `validate_light_novel.py` 的字数/对白/插图/漫画字段检查捕获——字数达标、对白格式看似正确——但正文可读性严重受损。本文件记录了实测出现的污染类型和一套可重复运行的扫描+修复流程。

## 污染类型与实例

### 1. 对话标记后缀残留（蛇形命名/英文动作描述）

LLM 在生成 `「台词」——角色名` 格式时，有时在角色名后粘附英文 fragment，像是内部伪标记泄漏：

| 实际输出 | 应为 |
|---|---|
| `「什么？」——陆远舟_joint` | `「什么？」——陆远舟` |
| `——苏晴_narrow her eyes_free-narrow` | `——苏晴` |
| `——陆远舟.pick up the envelope` | `——陆远舟拿起信封` |

**特征**：`——角色名` 之后紧跟下划线 `_` 或点 `.` 连接的英文/空格序列。

### 2. 英文单词/短语混入中文句子

LLM 在长段落生成到后半段时，注意力衰减，可能在中途混入英文片段：

| 实际输出 | 应为 |
|---|---|
| `校园-olds安防服务器机房炸开来` | `校园旧安防服务器机房的锁撬开时` |
| `他花了两天时间恢复了7年前～10个月以前` | `他花了两天时间恢复了七年前到十个月以前` |

**特征**：中文句子中出现非专有名词的英文单词，或中英文标点混用（`~`、`-` 连接中文数字）。

### 3. 乱码/非自然语言碎片

最严重的情况——输出中出现无法解析的字符序列，像是 token 化错误或解码异常：

| 实际输出 | 应为 |
|---|---|
| `五个手电的光九年前-1同扫过全盘y天服` | `五个手电的光一同扫过整个房间` |
| `江屿拀会议录存放在他桌前的电脑屏幕` | `江屿把恢复的影像投到他面前的电脑屏幕上` |
| `法太7十五年5月22日雏六点四十二分` | `十年前六月二十二日傍晚六点四十二分后的第一帧` |

**特征**：汉字+数字+英文字母+特殊符号无规则混合，语法断裂，语义不可读。

### 4. 纯阿拉伯数字代替中文数字

| 实际 | 应为 |
|---|---|
| `10年前 he 13岁` | `十年前他十三岁` |
| `7年前～10个月` | `七年前到十个月` |
| `身高大约180` | `身高大约一米八零` |

**特征**：正文中使用纯阿拉伯数字而非中文数字。注意：时间戳、度量值、引文中可以保留阿拉伯数字，但叙述性正文应统一中文数字。

### 5. 段尾/段中混入 ASCII 标记或残留 URL（2026-07-08 第三次复现）

LLM 初稿在段落结尾、对话标记后或插图标记前后，有时会粘附看似"内部伪标记"或"工具自报"的 ASCII 文本。这一类**跨越**类型1（对话标记后缀）与类型2（英文混入中文），且段尾的 ASCII 残留物此前未被列出：

LLM 初稿在段落结尾、对话标记后或插图标记前后，有时会粘附看似"内部伪标记"或"工具自报"的 ASCII 文本。这一类**跨越**类型1（对话标记后缀）与类型2（英文混入中文），且段尾的 ASCII 残留物此前未被列出：

| 实际输出 | 应为 | 子类 |
|---|---|---|
| `缝里漆黑。\|intellust` | `缝里漆黑。` | 段尾 ASCII 标记 |
| `缝里漆黑。\n\nhttps://hermes-agent.nousresearch.com/docs` | （删去） | 段后混入 URL |
| `她冒险去借 bald 镍镉电池` | `她冒险去找了老旧的镍镉电池` | 中英文夹杂（三字英文词，落入类型2） |
| `「a、勿、五八。」` | `「勿、五八。」` | 单 ASCII 字母开头对白 |
| `又被人用同一笔迹--更小、更急--重写了一遍` | `又被人用同一笔迹——更小、更急——重写了一遍` | ASCII `--` 代替 `——` |

**特征与对正确性的影响**：
- 段尾被追加的 `\|<小写英字>` 或一段 URL，与正文语义无关，像是工具/系统层泄漏的标记被一并写入。位置不固定（段末、章末钩子前、插图标记旁都可能），不破坏段落原语义但破坏可读性；URL 残留会让读者疑为正文抄袭/外链证据。
- 单个 ASCII 字母夹在中文标点之间（`「a、勿` 的 `a`），是单词首字母泄漏或半角全角混淆，破坏对白自然度。
- ASCII 半角连字符 `--` 被当作中文破折号 `——` 代用——多发生在长段连续对白或叙事内嵌短句。在 markdown 渲染器里 `--` 会被合并为单破折号 `—`，与中文 `——`（双破折号）字宽不同，阅读观感不一。

**对扫描脚本的影响**：现有 `scan_garbled()` 中 `en_words = re.findall(r'[a-zA-Z]{3,}', cleaned)` 可捕获 `bald`/`intellust`/`https` 等三字以上词，但**捕获不了**以下三类，需在 2026-07-08 之后的扫描中追加：
- 段尾 `\|[a-z]+` 模式（短标记，少于 3 字符或被 `\|` 分隔）→ 增 `re.findall(r'\\|[a-z]+\b', t)`
- 单 ASCII 字母夹中文标点 `[\u4e00-\u9fff「」、][a-zA-Z](?=[、，。：「」])` → 增 `re.findall(r'[\u4e00-\u9fff「」、][a-zA-Z](?=[、，。：「」])', t)`
- ASCII `--` 代用 `——` → 增 `re.findall(r'(?<=[\u4e00-\u9fff「」、])--(?=[\u4e00-\u9fff「」、])', t)`（限定在中文字符之间，排除 Markdown 标题下划线 `---` 行）

**重要：错误汉字（形近字）扫描不到**。例如本会话出现的 `庙哄`→应为"唬弄/空洞回响"、`淇着`→应为"捏着"——它们均为有效 Unicode 汉字，不是英文/数字/ASCII 噪声，正则扫不出来。只能靠写完后人工/LLM 通读首段和章末钩子段（污染最集中的段落）发现并修复，或用一个独立的"通读校对" LLM 二次检查兜底（喂该段，看它能否通顺读出、能否注意到形近字错误）。

## 扫描脚本

### 一键扫描所有章节

```python
import re, os, glob

def scan_garbled(content):
    """返回 (issue_type, matches) 列表，issue_type 对应下面的 5 类。"""
    issues = []
    
    # 类型1: 对话标记后缀残留
    marker = re.findall(r'——[^「\n]+_[\w\s]+', content)
    if marker:
        issues.append(('对话标记后缀', marker))
    
    # 类型2/3: 混入英文单词（排除 ILLUST 等结构标记）
    cleaned = re.sub(r'<!--.*?-->', '', content)  # 去掉 HTML 注释
    en_words = re.findall(r'[a-zA-Z]{3,}', cleaned)
    if en_words:
        issues.append(('英文混入', en_words))
    
    # 类型3: 乱码碎片（数字+字母+中文的无意义混合）
    garbled = re.findall(r'[\u4e00-\u9fff]+[0-9]+[a-zA-Z]+[\u4e00-\u9fff]*', content)
    if garbled:
        issues.append(('乱码碎片', garbled))
    
    # 类型4: 正文中的纯阿拉伯数字（粗略，需人工判断）
    # 仅标记肉眼可见的——数字后紧跟中文量词的
    arabic = re.findall(r'(?<![a-zA-Z\d.:/-])\d{1,4}(?=年|岁|个月|章|集|楼|米)', content)
    if arabic:
        issues.append(('数字待判断', arabic))
    
    # 类型5（2026-07-08 第三次复现）: 段尾/段中 ASCII 标记或残留 URL、单字母 ASCII、ASCII -- 代 ——
    # 5a: 段尾 \|<小写英字> 标记（"缝里漆黑。|intellust" 一类）
    tail_tag = re.findall(r'\|[a-z]+\b', cleaned)
    if tail_tag:
        issues.append(('段尾ASCII标记', tail_tag))
    # 5b: 段内 http(s):// URL
    urls = re.findall(r'https?://\S+', cleaned)
    if urls:
        issues.append(('URL残留', urls))
    # 5c: 单 ASCII 字母夹中文标点（"「a、勿" 一类）
    lone_ascii = re.findall(r'[\u4e00-\u9fff「」、][a-zA-Z](?=[、，。：「」])', content)
    if lone_ascii:
        issues.append(('单字母ASCII', lone_ascii))
    # 5d: ASCII -- 用在中文字符之间代 —— （排除 markdown 标题下划线 --- 行）
    ascii_dash = re.findall(r'(?<=[\u4e00-\u9fff「」、])--(?=[\u4e00-\u9fff「」、])', content)
    if ascii_dash:
        issues.append(('ASCII破折号代用', ascii_dash))
    
    return issues

# 扫描所有章节
for fpath in sorted(glob.glob('light_novel/ln*.md')):
    with open(fpath, 'r', encoding='utf-8') as f:
        content = f.read()
    issues = scan_garbled(content)
    if issues:
        print(f"\n{'='*50}")
        print(f"⚠ {fpath}")
        for itype, matches in issues:
            print(f"  [{itype}] ({len(matches)} 处):")
            for m in matches[:8]:
                print(f"    → {m}")
    else:
        print(f"✓ {fpath} 干净")
```

> **注**：以上 5 类检查均已由 skill 自带的 `scripts/verify_light_novel_delivery.py` 集成——它一次性扫 heredoc 残留 + 严格对白正则 + 漫画字段污染 + 上述乱码模式（除 5d ASCII 破折号之外类型1-5 均覆盖）。**优先使用 `verify_light_novel_delivery.py`，而不是手写扫描器**，手写脚本仅作为补漏/调试用途。

### 修复流程

1. **运行扫描** → 收集所有 issue。
2. **构建 `(old, new)` 替换列表** — 每条乱码对应一个正确中文表述。
3. **用 Python 批量替换** — 不要手动逐条 patch，用列表驱动 `str.replace`：
   ```python
   fixes = [
       ('——陆远舟_joint', '——陆远舟'),
       ('——苏晴_narrow her eyes_free-narrow', '——苏晴'),
       ('校园-olds安防服务器机房炸开来的时候', '校园旧安防服务器机房的锁撬开的时候'),
       ('十个手电的光九年前-1同扫过全盘y天服', '五个手电的光一同扫过整个房间'),
       # ... 完整列表
   ]
   for old, new in fixes:
       if old in content:
           content = content.replace(old, new)
           print(f"Fixed: {old[:40]}...")
       else:
           print(f"NOT FOUND: {old[:40]}...")
   ```
4. **写回 → 重新扫描 → 重新统计字数**（修复可能改变字数，需确认仍 ≥2500）。
5. **二次扫描确认** — `scan_garbled()` 返回空列表才算完成。

## 预防建议

### 生成阶段

- 中文长篇正文用中文 prompt 描述，不要在 `prompt` 中混入英文写作指令（如 `narrow her eyes` 这种动作描述会被 LLM 原样泄漏到输出中）。
- 单章长度超过 ~2800 字后，污染概率显著上升。分批生成（每批 2000-2500 字）后拼接，比一次性写 5000+ 字更可控。
- 生成结尾高潮段落（监控碎片揭示、多人对话密集场景）时，污染最集中。这些段落写完后优先跑乱码扫描。

### 新增污染形状：汉字夹英文再接汉字（2026-07 续写批段实测）

本次《量子恋爱算法》ln004–ln007 续写在 main-session 直接 `write_file` 路径下复现了一类**此前未收录**的污染形状——**整个外语 token / 程序标识符被嵌入连续中文句子中段，左右两侧紧贴汉字**。与类型2（英文混入）、类型5（段尾残留）不同，这类污染把英文词放在中文字串中间（有时单词本身在外语中有合法意义），正则 `[\u4e00-\u9fff]{1,3}[a-zA-Z]{2,}[\u4e00-\u9fff]{1,3}` 一扫即可定位。

| 实际输出 | 应为 | 来源 |
|---|---|---|
| 桌上的izando咖啡被FileSync检测到 | 桌面上的智能同步系统检测到 | 西班牙语 -ando 动名词 + 程序名混入 |
| 他确实可能 noch活动 | 他的手确实还在活动 | 德语副词混入 |
| 你父亲为什么不立n异用呢 | 你父亲如果不留给你用呢 | 拼音碎片 + 错字 |
| 那是]。 第一份量子情感地图 | 那是第一份量子情感地图 | Python 切片符号残留 |
| 一次咖啡时间襁oming主动让 | 一次咖啡时间主动让 | 襁褓之襁 +低的尾音 |
| 写__的机会看见你 | 写了有机会看见你 | 下划线占位符泄漏 |

**修复路径**：单条出现 → `patch` 精确替换；同时出现 ≥3 处并发不同的 shape-不匹配（如西语词 + 拼音碎片 + Python 符号三种并存）→ 不再逐条 patch，**整章 `write_file` 一次覆写**。原因：并发多 shape 时逐条 patch 易引入 note 8「patch 三重陷阱」的隐式误替换 / phantom 注入；一次覆写比 N 次 patch 总开销更低且更不易留二次污染。本次 ln007 即因此从首稿覆写一次过，而 ln004–ln006 改用逐条 patch 补漏——对单点污染两种路径都可行，但 batch neatness 显著以覆写为优。

**检测正则**（已加入 SKILL.md 强制自检 SOP）：
```python
re.findall(r'[\u4e00-\u9fff]{1,3}[a-zA-Z]{2,}[\u4e00-\u9fff]{1,3}', t)
```
对比 `scan_garbled()` 现有 `[a-zA-Z]{3,}` 整词正则只抓孤立英文，本正则抓的是**两侧夹中文**的英文 token，能定位上表所有六例（`izando` / `noch` / `FileSync` / `n异` / `襁oming`）。

### 验证阶段

`validate_light_novel.py` 已有的检查（H1、字数、对白、插图、漫画字段）**不够**——它不检测英文混入和乱码碎片。必须在标准验证后追加一次 `scan_garbled()` 扫描。本文件中的扫描脚本是手工执行的，尚未集成为 `validate_light_novel.py` 的内置检查项（未来可集成）。
