# Page/Panel 漫画脚本生成落地经验

本记录来自一次将 comic-script-generator 从 Scene 格式升级为 Page/Panel 漫画脚本、并生成 6 集连贯示例项目的实战调试。

## 关键结论

1. 格式通过不等于故事可用
   - 仅能通过 `validate_episode.py` 的 Page/Panel/字段校验，不代表故事连贯。
   - 必须额外检查每集标题、梗概、结尾钩子、下集提示是否形成递进链。

2. 生成连载前先写 episode beats
   - 不要直接套 42 个 Panel 模板，否则会得到大量重复 Panel。
   - 每集先列 6-8 个剧情 beat，再按 Page/Panel 展开。
   - 每集结尾钩子必须指向下一集标题/核心事件。

3. 最低连贯性检查
   - 第 N 集钩子是否被第 N+1 集开头承接。
   - 第 N+1 集标题是否兑现第 N 集下集提示。
   - 角色信任关系、线索、伏笔是否逐集推进，而不是重复相同场景。
   - `summary.md` 不能保留“待补充”。
   - `foreshadowing.md` 不能被画面描述、AI prompt、下集提示整段污染。

## update_project.py 伏笔提取坑点

自动提取伏笔要保守。不要从以下区域提取：

- fenced code blocks
- `**AI 提示词**`
- `**画面**`
- `**构图**`
- `**格子**`
- `**拟声**`
- `**转场**`
- `**气泡**`
- `**旁白**`
- `故事梗概`整段
- `本集结尾钩子`整段
- `下集提示`整段

推荐只提取显式字段：

```markdown
**伏笔**：银色手链会在蓝色霓虹下发热
**新增伏笔**：祁远相机会拍到未来一分钟
- 伏笔：阿墨会停在说谎者脚边
```

并要求长度限制，例如 6-80 字，避免整段说明进入 `foreshadowing.md`。

## 6 集连载结构样例

一个可用的递进链：

1. 第1集：建立主角和异常物件。钩子：相机拍到未来一分钟。
2. 第2集：兑现相机能力。钩子：黑猫停在祁远脚边。
3. 第3集：兑现黑猫识谎。钩子：祁远承认自己也失踪过。
4. 第4集：进入第13号巷口照相馆。钩子：母亲照片写着“不要让蓝光熄灭”。
5. 第5集：揭示蓝光和时间裂缝。钩子：录音变成现在的声音“别回头”。
6. 第6集：阶段性选择与反转。钩子：七天后的母亲照片，作为下一季入口。

## 推荐生成流程

1. 初始化项目，生成 `style_guide.md`。
2. 写角色档案和核心伏笔。
3. 先写 6 集标题 + 每集梗概 + 每集钩子 + 下集提示。
4. 检查链路：`ep1 hook -> ep2 title`、`ep2 hook -> ep3 title` ……
5. 每集列 6-8 个剧情 beat。
6. 每页使用一个 beat 展开为 5-7 个 Panel。
7. 跑：
   - `validate_episode.py`
   - `update_project.py`
   - `consistency_check.py`
8. 再人工/LLM抽查故事连贯性，而不是只看脚本 return code。
